# GAP CONTROLS — International product engineering standard v2.0
References verified 25 November 2026: [ISO/IEC 25010:2023](https://www.iso.org/standard/78176.html) product quality model; [WCAG 2.2](https://www.w3.org/TR/WCAG22/) AA target; [OWASP ASVS 5.0](https://asvs.owasp.org/) application security verification; [NIST SSDF 1.1](https://csrc.nist.gov/pubs/sp/800/218/final) secure development; [Core Web Vitals](https://web.dev/articles/vitals) performance targets. Benchmarks, not a claim of certification or full conformance.
## Planner mandate
For every ticket establish scope, baseline, desired outcome, acceptance evidence, dependencies, owner, security/data classification and risks. Design contract first: canonical schema, validated inputs, bounded request, stable error codes and HTTP statuses, scoped authorization, audit and idempotency. Never trust caller-supplied tenant, role or classification. API contract changes require compatibility/version strategy. Preserve production. Use the existing shared primitives before creating variants. Record an ADR for new architecture/dependency. No new package without reviewed inventory. Assign Coder, Tester and independent Reviewer; after two unsuccessful repairs stop and escalate. Record defects as proposed regression rules. Evaluate all ten quality gates using actual evidence and do not grant release authorization.
## Frontend
Single token system, consistent header/navigation/content/footer, shared card/metric/status primitives, semantic HTML and labels, local engineering diagrams with meaningful text alternatives and explicitly illustrative status. No stock images used as evidence. Responsive 320/375/768/1024/1440 CSS px, no document-wide horizontal overflow; complex tables may scroll within labeled region. Use semantic tables with column headings, explicit units and time zones, keyboard focus, status and error text, empty/loading/retry states, 44px interactive target design goal, reduced motion. Use locale-aware data format and logical direction styles; Arabic RTL requires dedicated translation and testing. Prefer data-driven widgets; label mock and live information distinctly. No customer data in staging.
## Backend
Server owns auth and tenant/project scope. Parse streaming JSON within byte budget; schema validate exact expected fields; stable errors, safe logs, no secrets. Preserve transaction boundaries, GC-05 reservations, unique idempotency key and scoped evidence. No live AI before approval. Current implementation is a staging graph adapter; other endpoints need inventory and phased migration.
## Acceptance matrix
WCAG AA: automated plus manual keyboard, focus, zoom, contrast, screen reader and reflow. Browser matrix: Chromium, Firefox, WebKit and representative physical iOS/Android devices. LCP <=2.5s, INP <=200ms, CLS <=0.1 at 75th percentile on mobile/desktop field data, plus controlled lab measurement. ISO product quality: functional suitability, performance, compatibility, interaction capability, reliability, security, maintainability, flexibility and safety mapped to evidence. ASVS/SSDF: verified session, tenant isolation, dependency provenance, test negatives, audit and release controls. Test outage, empty, malformed, oversized and replay. No inferred compliance from a successful build.
## Rollout
Shared foundation plus staging graph and AppShell integration are first increment. Migrate all modules by inventory, preserve behavior, compare screenshots at target widths, verify browser journeys and API contracts, establish accessibility/performance baseline, obtain independent acceptance. No production changes.
